3. AuthService (NEW: lib/services/auth_service.dart)
----------------------------------------------------
Methods: register(username, email, password), login(email, password),
logout(), refreshTokens(), getCurrentUser(), isLoggedIn(), plus
restoreSession() (launch validation) and adoptLegacyAccessToken() (migration).
- Calls POST $baseUrl/auth/register | /auth/login | /auth/refresh with the
  exact bodies the backend expects; parses {success, message, data}.
- IMPORTANT contract detail handled: refresh returns {accessToken,
  refreshToken} with NO user object, so the in-memory profile is preserved
  across rotation.
- On login/register: tokens -> secure storage, user object -> in-memory state.
- logout(): clears secure storage + in-memory user, notifies listeners.
- refreshTokens(): concurrent callers share one in-flight request. 401/403
  from refresh -> session destroyed (logout). Network failure -> session kept
  (offline-tolerant).
- Failures throw AuthException with the human-readable server message
  (including joined validation errors[]) for inline display.

4. STATE MANAGEMENT PATTERN (chosen + why)
------------------------------------------
Singleton ChangeNotifier + AnimatedBuilder/setState.
Why: HomeScreen uses plain StatefulWidget + setState, and every existing
service (CloudApiService, DatabaseService, EngineProcessManager) is a
"static final X instance" singleton. No Provider/Riverpod/Bloc exists in the
codebase. Introducing one just for auth would add a foreign paradigm, so
AuthService follows the established convention (ChangeNotifier is in
flutter/foundation — zero new dependencies). The login gate and sidebar
observe it via AnimatedBuilder; no Navigator plumbing needed.

5. ApiClient (NEW: lib/services/api_client.dart)
------------------------------------------------
Authenticated HTTP wrapper (get/post/patch/delete, per-request timeout).
- Attaches Authorization: Bearer <accessToken> automatically.
- On 401: exactly ONE silent refreshTokens() + ONE retry of the original
  request. If refresh fails, AuthService has already logged out, which flips
  AuthStatus -> unauthenticated and the UI gate redirects to login.
- All protected CloudApiService calls (fetchCurrentUser, updateProfile,
  saveGeneration, fetchMyGenerations, deleteGeneration, publish/unpublish)
  now route through ApiClient. Public calls (health, models, pricing, GPU)
  still use raw http. All existing public method signatures preserved.

(a) Lifecycle test (register -> login -> restart -> persists -> logout):
    register on "first launch" -> brand-new service instance on the same
    token store (simulated restart, status unknown) -> restoreSession()
    returns true, silently refreshes (tokens rotate access-1/access-2),
    reloads profile -> logout() wipes store + memory, status flips to
    unauthenticated (gate redirects to login).

(b) 401-refresh-retry path (NOT happy-path-only):
    - Expired access token -> 401 -> one refresh -> retry succeeds with the
      rotated token (Bearer headers asserted on both attempts).
    - Malformed/garbage refresh token -> exactly one refresh attempt ->
      session destroyed (store cleared, unauthenticated).
    - Concurrent 401s share a single refresh call (asserted: 1 refresh).
    - Widget tests: empty submit blocked with inline errors; malformed
      email rejected; weak password and bad username rejected offline.
